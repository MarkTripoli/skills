# Repository-required package transition

Read the producer's existing release workflow and the consumer's dependency configuration. Discover the package name, generated-client path when relevant, release/tag job, registry, and package manager from those repositories. A merged producer PR, release commit, version string, or successful source pipeline alone does not prove a package exists. This procedure applies only to a package boundary the selected code or tickets require.

1. Finish the applicable producer prerequisites before inspecting or changing dependent consumer branches. Identify the release/tag containing the required producer changes and the actual publication job result. If the run merged no producer change, inspect the applicable existing release. Read the package version from the released source, not a guessed next version.
2. Verify that exact version is reachable through the repository's authenticated registry tooling or package API, then resolve it in a clean consumer dependency state. Use the existing credentials without printing them. Publication failure or a pending release blocks affected consumers; continue independent PRs rather than merging against a local-only dependency.
3. If publication was skipped because the generated client or package did not change, compare the consumer's requirements with the available hosted version. Use that version only when it satisfies the reviewed change; otherwise record the missing release as a consumer blocker.
4. On each affected consumer branch, replace the local dependency with the verified hosted registry/version using the repository's dependency conventions. Regenerate lockfiles with its existing package tooling, inspect the resolved version and registry source, and run the relevant consumer checks. Do not hand-edit generated clients or assume a particular language, registry, or workspace tool.
5. Push the consumer branch, recheck its diff and current checks, handle new chain-related discussions, and merge in dependency order with the stack merge procedure. A later producer package change invalidates the selected version and requires this verification again for remaining consumers.
