Steer every Archon gate through prompts, never through pasted commands

Rule for the whole delivery flow: a person never types or pastes an `archon` command. Everything is done through prompts to an agent, and the agents run the commands. Today three places break this: (1) at every gate pause the human is told to run `archon workflow approve|reject <run-id>`; the `herd-next` gate mode stages an artifact read in the review pane but then reports the `archon workflow respond` command for the human to run; (2) the `deliver` skill's Archon reply prints `archon workflow wait`, `approve`, and `reject` as the person's next steps; (3) after one pause is handled nothing waits for the next one, so the person polls or discovers it.

Build a steward loop that fixes all three. The steward is an agent that stays with an Archon run until it completes, fails, or is abandoned: it blocks on `archon workflow wait <run-id> --json` in the foreground; at each pause it reads `archon workflow get <run-id> --json` (`status`, `working_path`, `metadata.approval.nodeId`, `.message`, `.decisions[].id`, `.resolved`), raises `herdr notification show` when inside Herdr, presents the gated artifact to the person in prose (the artifact's summary, its Verify and Known limits lists, and the decisions available), takes the person's answer in plain language (approval, or what should change), maps it to `archon workflow respond <run-id> <decision> "<text>"` itself, and waits again. Inside Herdr the steward runs in the review pane that `herd-next` gate mode already opens at the run's `working_path`; outside Herdr it runs inline in the session that started the run. The `deliver` skill, once it has started a run, hands to the steward immediately instead of printing commands: inside Herdr by opening the review pane through the `herd-next` gate mode, outside Herdr by becoming the steward in the same session. Use `judge.mjs feedback-intent` (the typed-judgment helper) to read the person's reply as approve or request changes when it is not one plain word, falling back to asking one clarifying question. Every answer template in the collection that names an `archon` command for a person to type is revised so the person is told what to say instead; grep for `archon workflow` across skills/*/references and skills/*/SKILL.md and fix each hit that addresses the human. The by-hand handoff fence (`/<skill> @<file>`) is unchanged; the Stop hook and the `herd-next` handoff mode already stage it. The validator must still pass: the steward's replies are terminal templates registered in ANSWER_INVENTORY. Acceptance: (a) starting a run with `/deliver` inside Herdr leaves the person with a review pane whose agent announces the first pause and asks for a decision, and no `archon` command in any reply; (b) the same outside Herdr, in the starting session; (c) saying `approve` or describing a change in that pane resolves the gate and the steward announces the next pause or the run's end; (d) `grep -rn 'archon workflow' skills/*/references skills/*/SKILL.md` shows no line that tells a person to run a command; (e) npm test passes; (f) prove (c) against a real paused run, for example a scratch `delivery-start` run with a bare remote that pauses at `confirm`, and record the observed JSON and the respond call in the verification and receipt artifacts.
