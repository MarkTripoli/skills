We need to do something about how we generate issues and how we do epics and things like that. I'm noticing we're not getting granular enough with our issues, which is resulting in larger merge requests and pull requests, which is problematic. We need to treat this as fully autonomous, meaning we can create nice, granular merge requests that are reviewable and testable, and then stack them up and deliver them quickly. We need to take a look at how we can make this a little better. Here's another repo we can even use for some inspiration on things.

https://github.com/rmorison/engineering-standards

Clarification: this task is one change, not multiple iterations. The skills themselves must let future work be sliced into granular, reviewable, testable merge requests that stack and deliver quickly.
