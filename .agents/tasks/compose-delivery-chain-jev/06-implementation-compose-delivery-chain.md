Five deviations carried from the child and accepted:

1. Every input is read as `${INPUTS_X:-$INPUTS.x}`, not the plan's literal `dir=$INPUTS.task_dir`. That is the convention for a composable block that is also run standalone (`workflows/delivery.md`, Archon note 13; `delivery-verify` and `delivery-app-test` do the same), and the plan's literal form cannot be exercised by `--dry-run --exec-code` or by the body-extraction test at all.
2. The fixed phase list's gate column for `research` is `-`, not the plan's `research|research|design`. The plan's own worked table three lines below shows `| research | yes | - |`, and research carries no gate anywhere in the system; treated as a typo in the plan and resolved toward the self-consistent value.
3. No fourth `bar()` sed extractor. `compose` always emits `bar: T.no`, a fixed 0.2, so the Bar column is `<= 0.20` whenever a probability was found and `-` otherwise.
4. `mkdir -p "$dir"` at the top of the body, mirroring `delivery-task`'s `create` node. The phase's own acceptance command passes `task_dir=.agents/tasks/fixture`, a path with no directory on disk.
5. The test sets `outline` to a confident no alongside `design`/`prd`/`tdd`/`app_test`, rather than the plan comment's "0.9 for the rest". With `outline` at 0.9 the Execution Strategy's own rule derives `planning=outline`, contradicting the same comment's expected `planning: "plan"`; the test exercises the `plan` branch without the contradiction. The `outline` branch of that rule has no test in this phase.
