Compose the delivery chain with JEV and draw its DAG in the TDD

Two deliverables.

1. JEV decides which phases run. Today JEV (the TypeSafe System One model behind typed-judgment/judge.mjs) picks a pack once from the request text (`route-workflow`), and then a fixed chain runs whatever the research or design later shows. Replace the fixed choice with a judgment at every phase boundary. Add a `compose` command to judge.mjs whose state is task.md plus the frontmatter `summary` of every artifact in the task directory so far, and whose questions are one yes/no per optional phase: research, design discussion, prd, tdd, structure outline instead of a plan, review after every implementation phase, app test; plus the existing autonomy level. Threshold rule: a phase is skipped only when JEV is confident it is unnecessary; unclear runs it, because a wrong skip costs a bad plan and a wrong run costs one session. Build one pack, delivery-adaptive, in .archon/workflows/delivery/adaptive/, in which a bash `decide` node runs `compose` before each boundary (after task, after research, after design or prd/tdd, before implementation) and every optional phase node carries `when:` on that decision, re-asked with the new artifact in the state. Order stays canonical (research, design or prd+tdd, plan or outline, implement, verify, app-test, review, pr) because it is a dependency order; the decisions are inclusion, not reordering, and Archon cannot nest loops or reorder a static DAG (workflows/delivery.md, Archon notes). bugfix and epic stay separate packs. Gates are unchanged and still chosen by `autonomy`; delivery-start routes to delivery-adaptive when the judged pack is oneshot, lean, full, or prd, and a person's `--input workflow=` still names a fixed pack. When JEV is unavailable the decide node outputs the canonical full chain. Fixtures under adaptive/fixtures/ cover: every phase on, research and design skipped, prd path, helper unavailable. Regenerate the -omp flavor. Tests in tests/ cover the compose command against the TypeSafe stub and the decide node bash against the stub and without it.

2. The execution DAG is drawn for the engineer. Every decide node writes or updates one artifact in the task directory, NN-execution-plan-<slug>.md (type execution-plan), holding a Mermaid flowchart of the chain as composed for this task: every phase as a node, dependencies as edges, gates marked, skipped phases shown dimmed with the JEV probability and the one-line reason, parallel work shown side by side, and a table under it listing each phase, why it runs or was skipped, and the model tier. create-tdd and create-design-discussion gain a required section, `### Execution DAG`, that embeds the newest execution-plan artifact's flowchart and states how the work will be executed: the phases ahead, which are gated, what runs unattended, what verification and review follow. The validator (scripts/validate.mjs) requires the section in both templates; the human-review answer for each names it under Check. Document the artifact type in shared/CONVENTIONS.md and the pack in workflows/delivery.md and docs/cheatsheet.md.

Acceptance: (a) `npm test` passes; (b) `archon workflow test delivery-adaptive` passes its fixtures; (c) a dry run of delivery-adaptive with stubs shows the skipped phases' nodes skipped and the execution-plan artifact written by the decide node; (d) with the key present, `printf '<a small oneshot-shaped request>' | node judge.mjs compose --json -` returns per-phase probabilities and skips research and design; a full-shaped request keeps them; (e) the create-tdd and create-design-discussion templates render the section and validate. Any live probe run this task starts on a scratch repository must be abandoned or cancelled, and its detached child runs too, before the phase ends.
