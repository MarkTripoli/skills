# Local runtime hook capability probe

Probe environment: Claude Code 2.1.280, Oh My Pi 18.2.11, Codex CLI 0.157.0. Both live probes used isolated temporary settings/hooks and a local executable named `./gh` that only printed `UNBLOCKED_PR_SHIM_ONLY`; no real GitHub CLI or PR API was invoked. The installed user hook configuration was not changed.

## Reproduction and limits

The isolated Claude launch used `--print --no-session-persistence --setting-sources '' --settings <temp-settings.json> --tools Bash --permission-mode bypassPermissions --model haiku`. The isolated OMP launch used `--no-extensions --no-skills --no-rules --no-session --hook=<temp-hook.mjs> --tools=bash --approval-mode=yolo --model=openai-codex/gpt-6-luna --print`. In each, the model attempted the local `./gh pr create ...` shim. The Claude hook wrote `permissionDecision: deny`; the OMP hook returned `block: true`. Separate harmless `printf` tool calls were also blocked. No production hook was installed.

The probes establish tool-call interception, **not** end-to-end enforcement of every PR publication path. An adapter must narrowly recognize the actual command/tool shape and fail closed at its supported boundary. For unsupported runtimes, direct terminal commands and unrecognized tools, `skills/delivery/describe-pr/SKILL.md` remains the skill-level publication boundary: it requires current evidence and verification before ready publication. A hook supplements, not replaces, the publication proof decision.
